# 数据库设计验证记录

执行：`npm.cmd run design:build`、`npm.cmd run design:test`。

在本地 PostgreSQL 18 的临时数据库实际执行完整 DDL，随后使用独立 `app_backend` 和 `app_agent` 登录连接测试。设计验证使用临时库；之后已将等价结构拆分为正式迁移 `004_frontend_auth_compat.sql` 至 `009_frontend_domain_completion.sql`，应用到当前 `app_dev`。

结果：**17 项检查通过，0 失败**（16 个子测试 + 1 个集成测试容器）。

- 66 张表、约束、视图、触发器和策略可创建。
- 游客、未核验、身份或本次登录核验过期的用户不可读取个人教务数据。
- 学生只看到本人已发布成绩、自己的选课课表。
- 教师只看到自己授课课表，不能读取学生成绩。
- 管理员没有个人成绩、课表和学籍资料的默认读取权限。
- 登录会话与核验记录必须属于同一用户；伪造 role 会话变量不提升权限。
- 停用账号后旧会话被撤销，不能再读取教务信息。
- 跨班写成绩、分数超过满分、将满分降低到已有分数以下、角色与身份不匹配被拒绝。
- 匿名公开帖子和评论不返回真实作者 ID/昵称；其他用户无法读原始作者映射。
- 普通用户无法冒充他人发帖或绕过评论审核。
- 私信仅会话成员可读，管理员和第三人不可读；加入第三人、非成员发消息和拉黑后的消息被拒绝。
- Agent 只能读取校园域安全公开视图，无成绩、学籍、身份核验、私信、订单和原始匿名帖子表读取权。
- 校园页面和商品只公开发布/在售内容；他人订单与明细不可读。
- 支付人必须匹配订单买家，累计待处理退款不能超过已付金额。
- 跑腿公开摘要不含加密地址、联系人、完整描述；非参与人不能读原任务详情。
- 跑腿发布人不能接自己的单；接单人与 accepted 申请必须在同一事务保持一致。

范围限制：这不是业务 API、并发压力、真实资金回调、活体识别或加密实现的验收。新增校园字段在测试中使用占位字节，实际 AES-GCM 编解码将在业务服务阶段实现。下单金额汇总/扣库存、状态迁移、工作流写入权限、可信教务导入和核验提供方对接仍须按设计文档实现。共享服务账号的信任边界见数据库设计文档。
